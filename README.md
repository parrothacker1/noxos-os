## Overview

`noxos-os` is the build recipe for the NoxOS ROM. It contains everything needed to pull, configure, and compile a custom AOSP image — except the AOSP source itself, which is ~250 GB and lives only on the build machine.

The pattern is identical to every real custom ROM project (LineageOS, GrapheneOS, CalyxOS): a small overlay repo that tells the `repo` tool where to find your custom bits, plus build scripts that run inside the AOSP tree.

```

│

    └── workflows/
        └── build.yml          ← self-hosted CI job (workflow_dispatch for now)
```

## How the Build Works

```
Developer / CI trigger
        │
        ▼
 ┌─────────────────────┐
 │  setup-instance.sh  │  ← Run once on a fresh EC2 Ubuntu instance
 │  • Install repo tool │    Installs: repo, JDK 17, AOSP build deps
 │  • Install JDK 17   │    (apt packages from AOSP's official list)
 └────────┬────────────┘
          │
          ▼
 ┌────────────────────────────────────────────────────┐
 │  sync.sh                                           │
 │  • repo init -u android.googlesource.com/...       │
 │    -b android-latest-release                       │
 │  • Copies local_manifests/ into .repo/             │
 │  • repo sync -c -j$(nproc)   ← ~250 GB, once only │
 │    (EBS volume persists between Spot interruptions)│
 └────────┬───────────────────────────────────────────┘
          │
          ▼
 ┌──────────────────────────────────────────────┐
 │  build.sh                                    │
 │  • source build/envsetup.sh                  │
 │  • lunch aosp_cf_x86_64_phone-userdebug      │
 │  • m dist   ← produces OTA zip + img files   │
 └────────┬─────────────────────────────────────┘
          │
          ▼
   GitHub Release asset
   noxos-<ver>-<YYYYMMDD>-<channel>-<device>.zip
          │
          ▼
   noxos-server picks it up → publishes OTA manifest
```

## EC2 Infrastructure Design

AOSP requires substantial hardware. A local machine can't do it.

| Resource | Spec | Reason |
|----------|------|--------|
| Instance | `m5.2xlarge` (8 vCPU, 32 GB RAM) | Soong dependency analysis alone needs ~30 GB RAM |
| Storage | gp3 EBS, ~400 GB, `DeleteOnTermination: false` | Persists the 250 GB `repo sync` across Spot interruptions |
| Spot behavior | `InstanceInterruptionBehavior: stop` | Instance stops (not terminates), EBS survives |
| Estimated cost | ~$0.05–$0.15/hr Spot | Check `aws ec2 describe-spot-price-history` before launching |

The `repo sync` happens **once** on the EBS volume. Subsequent builds resume from cached state — a Spot interruption costs only the time since the last incremental build checkpoint, not a full re-sync.

## Local Manifest Overlay

`local_manifests/roomservice.xml` is currently **empty** by design. Phase 1 builds a completely unmodified Cuttlefish image to verify the pipeline before touching the OS.

Custom overlays land here in later phases:


## Boot Animation

`branding/bootanimation.zip` is a fade-in animation of the NoxOS mark, generated by `branding/generate-bootanimation.sh` from the canonical `assets/branding/logo-mark.svg` (source of truth in the root repo).

> **Not yet wired into any build target.** Boot animations are referenced from a device tree (`device/<vendor>/<device>/`), which doesn't exist until P3/P4 (lightweight base work). Revisit then.

---

## Phase 1 Exit Criterion

> An **unmodified Cuttlefish virtual device** (`aosp_cf_x86_64_phone-userdebug`) boots successfully after running the three infra scripts in order on the EC2 instance.

Once that's confirmed, cut the first GitHub Release and register the self-hosted runner so CI automation can take over.
